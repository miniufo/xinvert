## 大迭代次数验证（动态间隔的核心收益）

动态间隔随 mxLoop 缩放，使 host-device 同步次数基本恒定：

| mxLoop | tolerance=0 间隔 | 同步次数 | tolerance>0 间隔 | 同步次数 |
|--------|-----------------|---------|----------------|---------|
| 1000 | 50 | 20 | 20 | 50 |
| 5000 | 250 | 20 | 100 | 50 |
| 10000 | 500 | 20 | 100 | 100 |
| 100000 | 500(cap) | 200 | 100(cap) | 1000 |

**实测耗时（512×512, tolerance=0）**：

| mxLoop | CPU (s) | GPU (s) | 加速比 | 备注 |
|--------|---------|---------|--------|------|
| 1000 | 1.6933 | 0.1418 | 11.9x | 基准 |
| 10000 | 16.9593 | 0.9896 | 17.1x | 迭代 10x，GPU 仅慢 7x → 加速比 ↑ |

**实测耗时（1024×1024, tolerance=0, GPU）**：

| mxLoop | GPU (s) | 估算 CPU 加速比 |
|--------|---------|---------------|
| 1000 | 0.4411 | ~15.6x |
| 10000 | 3.5606 | ~19.2x (CPU 按线性估算 ~68.5s) |

**结论**：迭代次数越多，动态间隔的收益越大——因为 host sync 次数被压到恒定 20 次（tolerance=0），GPU 的固定开销不随迭代数增长，加速比从 12x 升到 17~19x。

## 正确性验证
- `test_CpuGpuConsistency.py`: **PASS** (mxLoop=20000, tolerance=1e-10)
  - CPU-GPU 差异 1.1e-6（< 1e-3 阈值）
  - 注：比第一轮的 9.35e-10 略大，因收敛场景检查间隔从 20→100，收敛判定时机略有差异（Red-Black vs Gauss-Seidel 轨迹在额外迭代中发散）。对极严 tolerance 场景可把 `[10,100]` 上界调小。

## 优化措施

### 第一轮：稀疏化收敛检查
- 非检查迭代只跑 Red+Black kernel，跳过 norm 计算 + host sync
- tolerance=0 时只需 overflow 检测

### 第二轮：动态检查间隔 + 通用框架
1. **`_compute_check_interval(mxLoop, tolerance)`**：间隔随 mxLoop 缩放
   - tolerance=0（固定迭代）：`clamp(mxLoop/20, 50, 500)`，仅需 overflow 检测
   - tolerance>0（真实收敛）：`clamp(mxLoop/50, 10, 100)`，平衡及时停止与 sync 成本
2. **`_evaluate_gpu_norm(...)`**：提取 norm 收敛评估逻辑，与 CPU `absNorm*` 指标一致
   - 2D/3D/general/biharmonic 等 GPU wrapper 可直接复用，只需写各自 update kernel

## 可选的后续优化方向

| 方向 | 收益 | 风险 | 扩展性 |
|------|------|------|--------|
| norm kernel block-level reduction | 中（大网格原子竞争） | 低 | 通用，3D 更受益 |
| shared memory tile for SOR | 高（减少 global 访存） | 中（RB 隔点利用率减半，需 benchmark） | 各维度独立实现 |
| block size 调优 (32×8) | 低~中 | 低 | 通用 |
| pinned memory 加速 copy_to_host | 低 | 低 | 通用 |
| 系数缓存 (A/B/C/F 跨求解复用) | 高（动画逐帧场景） | 中（需改 API） | 通用 |
| max\|update\| 轻量收敛信号 | 中（替代全数组 norm） | 中（收敛指标变化） | 对 3D 尤其有意义 |
